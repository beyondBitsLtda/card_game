🧠 1️⃣ — Como o viewport torna o site responsivo tecnicamente?

A linha:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

🔍 Explicação técnica:

O viewport é a área visível do site dentro da tela do dispositivo (como a janela de um navegador no celular ou computador).
Por padrão, em dispositivos móveis, os navegadores antigos “enganavam” as páginas, simulando uma largura de tela de 980px (como se fosse um desktop).

➡️ Isso fazia os sites parecerem minúsculos, obrigando o usuário a dar zoom.

📱 O que o meta viewport faz:

Quando você define:

width=device-width


Você diz ao navegador:

“Use a largura real do dispositivo como base do layout.”

Ou seja:

Se o celular tiver 360px de largura, o navegador usa 360px.

Se for um monitor de 1920px, usa 1920px.

E o trecho:

initial-scale=1.0


Diz:

“Comece o zoom da página em 100% (1.0x), sem aproximar nem afastar.”

📊 Resultado técnico:

O CSS passa a responder corretamente aos breakpoints de media queries (@media (max-width: 600px) etc).

O layout se adapta conforme a largura do dispositivo.

Isso é a base da responsividade verdadeira no HTML.

🎨 2️⃣ — Por que o CSS é importado no <head> e não em outro lugar?
<link rel="stylesheet" href="css/style.css">

🧩 Motivo técnico:

O navegador lê o HTML de cima pra baixo.

Quando ele chega no <head>, ele:

Carrega as configurações iniciais (meta tags, título, estilos, etc).

Depois começa a renderizar o corpo (<body>) visualmente.

👉 Se o CSS estiver no head, ele é carregado antes da renderização.
Assim, a página já aparece estilizada.

⚠️ Se fosse colocado depois:

O navegador exibiria o HTML sem estilo por alguns milissegundos, e depois aplicaria o CSS (efeito chamado FOUC — Flash of Unstyled Content).

Isso deixa a experiência feia e inconsistente.

Além disso, é uma má prática de performance e acessibilidade.

✅ Por isso, CSS sempre no <head>
e JavaScript geralmente no final do <body>, pra não travar o carregamento da página.
